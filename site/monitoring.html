Scheduled monitoring

Watch a public page for changes.

Create a monitor on an active paid plan. Apex checks the page on your chosen schedule and sends a signed HTTPS event when its content changes.

Create a monitor

POST /v1/monitors with your bearer key. The minimum interval is one hour and the maximum is 30 days. Monitors obey the source site's robots.txt rules. The first successful check establishes a baseline and does not send an event.

{
  "url": "https://example.com/pricing",
  "webhook_url": "https://your-service.example/webhooks/apex",
  "interval_seconds": 86400,
  "confirm_recurring": true
}

Each successful plain-page check uses one credit; failed checks are refunded. The response shows the maximum expected credits over 30 days. There are no automatic overages: a monitor pauses if credits run out. The plan monitor limit and active monitor count are included in GET /v1/usage.

Each change event includes a stable event ID, monitor ID, source URL, previous and current content hashes, page title when available, and a bounded text diff. The webhook receiver can deduplicate retries by event ID.

Verify notifications

The create response includes a monitor-specific signing_secret once. Store it securely. Notifications include X-Apex-Event-Id and X-Apex-Signature: t=<unix-seconds>,v1=<hex>. Verify the HMAC-SHA256 using the signing secret as the key and timestamp + "." + exact raw request body as the message. Reject stale timestamps and deduplicate by event ID. Apex retries failed deliveries with bounded backoff and never follows redirects.

import hmac, hashlib
expected = hmac.new(secret.encode(), timestamp.encode() + b"." + raw_body,
                    hashlib.sha256).hexdigest()
valid = hmac.compare_digest(expected, received_signature)

Manage monitors

  • GET /v1/monitors lists this account's monitors.
  • POST /v1/monitors/pause or /resume with {"id":"…"} changes a monitor's state.
  • GET /v1/monitors/{id}/events shows recent events and delivery attempts.
  • DELETE /v1/monitors/{id} deletes the monitor and its event history.

Monitor operations are also available over the hosted MCP server. A monitor reads only public URLs, uses no browser login state, and does not bypass access challenges or robots exclusions.
