Migration guide

Keep the API shape. Choose the engine.

Apex exposes a limited Firecrawl v2-compatible HTTP surface for migration experiments. Configure your client with the Apex API base URL and your Apex bearer key. This is a compatibility subset, not a drop-in implementation of every Firecrawl SDK method.

Source status: these routes are implemented on the current draft branch. They are not live until a reviewed production release.

Supported routes

  • POST /v2/parse and GET /v2/parse/formats: upload and inspect supported PDF, DOCX, HTML, plain text, JSON, and XML documents. Uploads are limited to 12 MiB and cost one credit per document. Outputs include markdown, text, links, HTML where present, PDF pages, and metadata. Only formats and onlyMainContent:true are accepted options.
  • GET /v2/team/credit-usage and GET /v2/team/credit-usage/historical: current allowance/period metadata and monthly credit totals. Pass ?byApiKey=true for per-key rows with stable opaque IDs and key labels. Usage created before per-key tracking was added is returned as unattributed.
  • POST /v2/scrape: markdown, main-content html, full-source rawHtml (capped at 500k characters), links, images, selector-driven attributes, screenshot, and schema or prompt driven json; maxAge; onlyMainContent:true; waitFor (0–5000 ms after page load); bounded click, wait, and scroll actions. The images format returns deduplicated, resolved URLs from image and responsive-image markup, up to 2,000 URLs per page. It does not download image bytes or perform OCR. The attributes format accepts up to 50 CSS selector/attribute pairs and returns at most 200 values per selector; oversized responses include a warning. Batch and crawl support the same image and attributes formats. minAge and lockdown:true select cache-only reads; cache misses return 404 (SCRAPE_NO_CACHED_DATA or SCRAPE_LOCKDOWN_CACHE_MISS) and never contact the target. Cache-only reads still require a cached, recent robots.txt policy, and do not support JSON extraction, screenshots, or browser actions. Lockdown accepts cached pages up to two years old by default; maxAge can lower that limit. Responses include Firecrawl-style success/data with source metadata and an Apex credit extension.
  • POST /v2/map: sitemap-based URL discovery, optional text filter, and limit up to the Apex account limit.
  • POST /v2/search: web, news or image search when the operator has configured an eligible search provider. It accepts one or more distinct Firecrawl sources per request, as strings or objects; limit applies per source, results are grouped under matching data keys, and partial provider failures appear in sourceErrors alongside successful result arrays (["web"], [{"type":"news"}], [{"type":"images"}]), plus the pdf category and mutually exclusive includeDomains or excludeDomains filters with 1–50 hostname values. The PDF category appends filetype:pdf to the query and retains only results whose URL path ends in .pdf; it does not use a dedicated PDF index. News uses Tavily's news topic or Exa's news category; image search uses Brave's dedicated index with strict SafeSearch. Filters are forwarded to providers and enforced against normalized result hostnames. Results include Firecrawl-style position numbers and provider dates for news when available; images include a direct image URL, source-page URL and available dimensions. Web/news requests may include scrapeOptions for markdown, html, rawHtml, links, images or screenshot; each result page is scraped through Apex safety checks and metering, with per-result scrape failures and aggregate creditsUsed reported. Search and each page scrape consume credits separately. Image-result scraping, JSON extraction and summary formats are not supported through this option. Firecrawl SDK origin telemetry is accepted but not stored by Apex. Alexandria and research/developer/government indexes are not implemented. It does not search Apex saved pages.
  • POST /v2/crawl, GET /v2/crawl/active, GET /v2/crawl/{id}, GET /v2/crawl/{id}/errors, DELETE /v2/crawl/{id}: same-site background crawl, account-scoped active-job listing, durable job status, recorded page failures, and cancellation; supported formats include markdown, html, rawHtml, links, images, attributes, screenshot, and provider-backed JSON. scrapeOptions.waitFor applies a 0–5000 ms bounded wait to each page. Include/exclude path regular expressions, full-URL matching, and query-parameter deduplication are supported within bounded limits.
  • POST /v2/interact, GET /v2/interact, POST /v2/interact/{id}/execute, and DELETE /v2/interact/{id}: short-lived, account-owned browser contexts with explicit public-origin allowlists and click/wait/scroll actions. Each account may hold one session per API process; each process has two concurrent browser slots. Multi-process session affinity is not yet implemented.
  • POST /v2/batch/scrape, GET /v2/batch/scrape/{id}, GET /v2/batch/scrape/{id}/errors, and DELETE /v2/batch/scrape/{id}: asynchronous, account-scoped batch jobs with persisted status/results, cancellation and per-URL errors. Job size follows the account's crawl page cap; processing uses Apex account concurrency and native batch slices. waitFor is supported from 0–5000 ms per page. Optional webhook accepts url, events (started, page, completed) and up to 16 KiB of metadata. Callback URLs must use public HTTPS on port 443; redirects are not followed. The create response returns a one-time signingSecret. Apex signs the exact request body in X-Apex-Signature: t=...,v1=... using HMAC-SHA256 over timestamp + "." + raw_body. Delivery is at-least-once with bounded retries; deduplicate using X-Apex-Event-Id. Page callbacks over 128 KiB carry metadata and a truncation marker; retrieve full content from batch status.

Example

curl https://webscraper.apexflowlabs.com/v2/scrape \
  -H "Authorization: Bearer $APEX_SCRAPER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com","formats":["markdown","links"]}'

Reuse the official SDK

The current official Firecrawl Node and Python clients accept a custom API origin. Point an existing client at Apex and use an Apex API key to try the supported routes. Selected v2 calls are tested against the official clients. Unsupported options fail explicitly; SDK defaults Apex cannot honor are surfaced as response warnings. This does not establish full Firecrawl SDK parity.

import { Firecrawl } from "firecrawl";

const scraper = new Firecrawl({
  apiKey: process.env.APEX_SCRAPER_API_KEY,
  apiUrl: "https://webscraper.apexflowlabs.com",
});

const page = await scraper.scrape("https://example.com", {
  formats: ["markdown"],
});
console.log(page.markdown);

Python uses the same base origin with Firecrawl(api_key=..., api_url="https://webscraper.apexflowlabs.com"). See the official Node SDK and Python SDK documentation.

Limits and semantics

  • Apex meters requests using Apex credits and rate/concurrency limits. Rendered pages, search, and other options can have different credit costs; read creditsUsed and the Apex usage endpoint.
  • Document parsing charges one credit per uploaded file, including PDFs up to 100 pages; it does not provide image OCR, raw binary output, audio/video extraction, prompt-injection detection, or PII redaction.
  • Apex obeys the target site's robots.txt. Crawl remains same-site and bounded by the account plan. Include/exclude regular expressions are limited to 20 patterns of 200 characters each and use a restricted syntax to prevent pathological matching. The adapter rejects requests to ignore robots rules, follow external links, or enable subdomains.
  • JSON extraction requires an Apex-configured model provider and a paid hosted plan. It costs 150 credits in addition to page retrieval; Apex validates returned JSON against the supplied schema and exposes validation details as jsonValidation when needed. With no schema, supply a prompt; Apex uses a generic object schema. Interactive sessions cost 3 credits to create and 3 per action request, last up to 15 minutes, obey robots.txt, and only fetch GET/HEAD resources from explicitly allowed public origins. They do not expose CDP, live video, arbitrary code execution, form submission, cookie profiles, or authenticated login. Summaries, image OCR, provider indexes, Firecrawl Agent, and persistent profiles remain unsupported. HTML and rawHtml use Apex's bounded main-content and source-document representations, respectively. Custom batch concurrency remains unsupported. Unsupported formats/options return a clear error where the route is defined.
  • Whole-web search needs an operator-configured provider and may be unavailable. Apex's native /v1/search searches only the account's saved pages.
  • Adapter behavior may differ in defaults, caching, error details, pagination and lifecycle fields. Check each response and test your workload before migrating production traffic.

See the Apex OpenAPI specification, monitoring guide, and Firecrawl's current API reference.
