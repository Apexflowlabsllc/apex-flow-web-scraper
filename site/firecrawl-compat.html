Migration guide

Keep the API shape. Choose the engine.

Apex exposes a limited Firecrawl v2-compatible HTTP surface for migration experiments. Configure your client with the Apex API base URL and your Apex bearer key. This is a compatibility subset, not a drop-in implementation of every Firecrawl SDK method.

Source status: these routes are implemented on the current draft branch. They are not live until a reviewed production release.

Supported routes

  • POST /v2/scrape: markdown, main-content html, full-source rawHtml (capped at 500k characters), links, screenshot, and schema or prompt driven json; maxAge; onlyMainContent:true; bounded click, wait, and scroll actions. Responses include Firecrawl-style success/data with source metadata and an Apex credit extension.
  • POST /v2/map: sitemap-based URL discovery, optional text filter, and limit up to the Apex account limit.
  • POST /v2/search: web search only when the operator has configured an eligible search provider. It does not search Apex saved pages.
  • POST /v2/crawl, GET /v2/crawl/{id}, DELETE /v2/crawl/{id}: same-site background crawl, durable job status and cancellation; supported formats include markdown, html, rawHtml, links, and screenshot.
  • POST /v2/batch/scrape, GET /v2/batch/scrape/{id}, GET /v2/batch/scrape/{id}/errors, and DELETE /v2/batch/scrape/{id}: asynchronous, account-scoped batch jobs with persisted status/results, cancellation and per-URL errors. Job size follows the account's crawl page cap; processing uses Apex account concurrency and native batch slices.

Example

curl https://webscraper.apexflowlabs.com/v2/scrape \
  -H "Authorization: Bearer $APEX_SCRAPER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com","formats":["markdown","links"]}'

Limits and semantics

  • Apex meters requests using Apex credits and rate/concurrency limits. Rendered pages, search, and other options can have different credit costs; read creditsUsed and the Apex usage endpoint.
  • Apex obeys the target site's robots.txt. Crawl remains same-site and bounded by the account plan. The adapter rejects requests to ignore robots rules, follow external links, enable subdomains, or use unsupported path patterns.
  • JSON extraction requires an Apex-configured model provider and a paid hosted plan. It costs 150 credits in addition to page retrieval; Apex validates returned JSON against the supplied schema and exposes validation details as jsonValidation when needed. With no schema, supply a prompt; Apex uses a generic object schema. Summaries, image OCR, provider indexes, persistent browser sessions, Firecrawl Agent, and Interact are not implemented by this adapter. HTML and rawHtml use Apex's bounded main-content and source-document representations, respectively. Batch-specific features such as custom concurrency and webhooks are not implemented. Unsupported formats/options return a clear error where the route is defined.
  • Whole-web search needs an operator-configured provider and may be unavailable. Apex's native /v1/search searches only the account's saved pages.
  • Adapter behavior may differ in defaults, caching, error details, pagination and lifecycle fields. Check each response and test your workload before migrating production traffic.

See the Apex OpenAPI specification, monitoring guide, and Firecrawl's current API reference.
